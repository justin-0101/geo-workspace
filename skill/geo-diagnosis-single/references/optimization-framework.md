# GEO 优化方案框架

## 核心定位

GEO 诊断的商业价值不在于“问几个模型得到截图”，而在于把模型回答中的缺口转化为企业能执行的内容资产、官方信息源、第三方背书和持续迭代机制。

最终交付应包括：

1. 当前可见度结论：模型是否知道、是否提及、是否推荐、是否混淆。
2. 问题归因：为什么模型没有提到或描述不准。
3. 针对性优化方案：要补哪些信息源、内容资产、案例、页面和结构化资料。
4. 可落地执行清单：按 P0/P1/P2、负责人、产出物、周期和验收标准拆解。

## 四类常见 GEO 缺口

### 1. 身份缺口 Identity Gap

表现：

- 模型不知道企业是谁。
- 品牌题回答很短、模糊或把企业和别的主体混淆。
- 没有统一的品牌全称、简称、地址、业务范围、服务区域。

优化方向：

- 建立官方基础信息页。
- 统一品牌 NAP：Name / Address / Phone。
- 在多个可信平台沉淀一致的公司介绍。
- 形成“标准事实卡”：成立时间、服务区域、主营业务、客户类型、核心优势、联系方式。

### 2. 内容缺口 Content Gap

表现：

- 非品牌高意图问题里没有出现企业。
- 模型只推荐大平台、通用品牌或泛泛建议。
- 企业没有覆盖用户真实搜索/提问场景。

优化方向：

- 围绕诊断问题反向建设内容资产。
- 每个高意图问题对应 1 篇“可被引用”的权威内容。
- 内容必须具体：价格、流程、案例、适用对象、避坑、对比。
- 用用户问题做标题，而不是只写企业宣传文案。

### 3. 权威缺口 Authority Gap

表现：

- 模型提到企业但不给推荐。
- 推荐时缺少理由或来源。
- 没有第三方资料证明企业可信。

优化方向：

- 增加客户案例、服务数据、行业经验、资质说明。
- 发布在高权重第三方平台：企查查/天眼查可验证信息、本地商家平台、行业目录、知乎/百家号/公众号/小红书等。
- 获取客户评价、问答、服务案例、媒体/平台收录。

### 4. 结构缺口 Structure Gap

表现：

- 模型能看到信息，但抓不到关键卖点。
- 企业资料散乱，无法形成“推荐理由”。
- 页面没有结构化标题、FAQ、对比表、Schema/JSON-LD。

优化方向：

- 把企业信息做成模型容易抽取的结构：FAQ、清单、表格、案例块、服务页。
- 每个页面明确回答一个问题。
- 给出可验证事实，不堆形容词。
- 重点页面加入结构化数据和清晰内链。

## 优化方案输出结构

每份优化方案应包含：

1. 诊断摘要：3-5 条发现，每条绑定 task_id。
2. 根因判断：身份 / 内容 / 权威 / 结构 四类缺口。
3. 30 天执行计划：先建基础信息源和高意图内容。
4. 60 天执行计划：补案例、第三方背书、平台分发。
5. 90 天执行计划：复测、修正、扩大问题覆盖。
6. 内容资产清单：标题、目标问题、发布位置、核心要点。
7. 官方信息资产清单：官网/落地页/公众号/第三方主页/FAQ。
8. 验收标准：下次 GEO 复测看哪些指标。

## P0 / P1 / P2 优先级

### P0：必须先做，否则模型没有可信事实源

- 官方基础信息页或替代官方主页。
- 统一品牌事实卡。
- 高意图问题的基础 FAQ。
- 纠正主体混淆和错误信息。

### P1：提升自然提及和推荐理由

- 3-5 篇高意图内容资产。
- 2-3 个真实客户案例。
- 本地/行业服务页。
- 对比型内容：本地服务商 vs 大平台 / 自建团队 / 通用工具。

### P2：扩大覆盖与持续迭代

- 多平台分发。
- 第三方问答和客户评价。
- 周期性复测。
- 新问题库扩展。

## 验收指标

下次复测至少关注：

- 非品牌题自然提及数是否增加。
- 明确推荐数是否增加。
- 品牌题是否能准确说清主营业务、区域和优势。
- 对比题中是否出现更合理的推荐边界。
- 来源引用是否能命中官方/高可信页面。
- 错误事实和主体混淆是否减少。

## GEORank 工具产出物(v2.0 新增)

借鉴 GEORank 模块 6(结构化),把 4 类缺口补强为"可被模型引用的结构化资产"。

### 工具产出物清单

| 产出物 | 适用缺口 | 优先级 | 验收标准 |
|---|---|---|---|
| JSON-LD(Organization + LocalBusiness) | 身份缺口 | P0 | Schema.org validator 通过 |
| JSON-LD(FAQPage) | 内容缺口 | P1 | 至少 5 个 Q&A 覆盖 Q01-Q05 |
| JSON-LD(Service) | 内容缺口 | P1 | 主营业务 3-7 个全列出 |
| JSON-LD(Review) | 权威缺口 | P2 | 仅引用第三方平台真实评价,不得伪造 |
| llms.txt | 身份缺口 + 结构缺口 | P0 | 200 字摘要 + NAP + 7 段结构 |
| AI 友好度评分 | 4 类缺口综合 | 每次诊断后 | 6 维度,总分 0-100,趋势向上 |
| 拓词清单(4 层 + 推荐型) | 内容缺口 + 权威缺口 | 配置阶段 | 8 题 → 16-30 题,推荐型关键词 ≥ 10 |
| 知识库草稿(company_kb.md) | 身份缺口 + 内容缺口 | P1 | 自动从 observations.jsonl 抽取 |
| GEO 标题生成器 | 内容缺口 + 结构缺口 | P1 | "{地域}+{行业}+{服务}+{差异化}" 模板 |

### 与 P0/P1/P2 的对应关系

- **P0(必须先做)**:JSON-LD Organization/LocalBusiness + llms.txt + AI 友好度评分基线 + 拓词基线
- **P1(提升自然提及和推荐理由)**:JSON-LD FAQPage/Service + 拓词扩题 + 知识库草稿 + 标题生成
- **P2(扩大覆盖与持续迭代)**:JSON-LD Review + 多平台分发 + 复测评分对比

### 详细规范

每个工具产出物的字段、格式、验证方式见 `references/tools-output-spec.md`。

### 与 GEORank 对齐

工具产出物对应 GEORank 模块 6(结构化)的 5 大产出物:
1. JSON-LD 生成器 → `scripts/generate-schema.py`
2. llms.txt 生成器 → `scripts/generate-schema.py`
3. AI 友好度评分 → `scripts/ai-friendliness-score.py`
4. GEO 标题生成器 → `scripts/render-report.py` 段 4
5. 知识库生成器 → `scripts/render-report.py` 段 11

总览与对齐关系见 `references/georank-7-module-alignment.md`。
